# План продаж Ozon

Трекер выполнения плана продаж Ozon. Показывает план и факт по кабинетам, категориям и артикулам, ЧП и рентабельность. Есть симулятор «объём или маржа» и история по месяцам.

## Как устроено

- **Сайт** — одна страница `site/index.html`, опубликована на GitHub Pages: https://vladoskosolapovv.github.io/ozon-plan/
- **Данные** лежат в отдельном приватном репозитории `vladoskosolapovv/ozon-plan-data`. Сайт пишет туда через GitHub API по ключу, который хранится в браузере.
  - `months/ГГГГ-ММ.json` — план месяца.
  - `facts/ГГГГ-ММ_ДД-ДД.json` — факт за период из выгрузок.
  - `settings/catalog.json` — настройки: какие артикулы в каком кабинете на ведении и к какой категории относятся.
  - `history.csv` — сводка план/факт по месяцам. GitHub показывает её таблицей.
  - Каждое сохранение — отдельный коммит, поэтому любую прошлую версию плана можно открыть в истории репозитория данных.
- **В этом репозитории нет данных**, только код. Поэтому его можно держать публичным: без ключа сайт ничего не показывает.

## Как выходят обновления

1. Изменения приходят pull request'ом в этот репозиторий.
2. GitHub Actions сам проверяет страницу: разбирает код и открывает сайт в браузере. Если проверка прошла, у PR будет зелёная галочка.
3. Нажимаете **Merge pull request**, и через 1–2 минуты сайт обновлён по той же ссылке (`.github/workflows/pages.yml`).

Откатить обновление: на странице слитого PR нажать **Revert**, затем смержить появившийся PR.

## Настройка (один раз)

1. Создать приватный репозиторий `ozon-plan-data`.
2. Сделать этот репозиторий публичным: Settings → General → Danger Zone → Change visibility. GitHub Pages бесплатно работает только с публичными репозиториями.
3. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
4. На каждом устройстве открыть сайт и ввести ключ. Ключ — fine-grained token с доступом только к `ozon-plan-data`, право Contents: Read and write. Как его создать, сайт подскажет сам.
